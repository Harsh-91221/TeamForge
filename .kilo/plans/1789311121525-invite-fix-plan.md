# Invite Feature Fix Plan

## Issue Summary
The invite feature fails due to a base URL configuration mismatch: `frontend/vite.config.ts` hardcodes `base: '/TeamForge/'`, but local development should serve from root. The error "The server is configured with a public base URL of /TeamForge/ - did you mean to visit /TeamForge/ instead?" comes from Vite when accessing the invite route outside the `/TeamForge/` base path.

## Decisions Confirmed
- Preserve GitHub Pages production deployment at `/TeamForge/` and serve local development from root `/`.
- Add focused automated tests for the invite flow.

## Root Cause Analysis
1. **Base path mismatch**: `vite.config.ts` forces all requests/assets under `/TeamForge/`. In dev, the app runs at `http://localhost:5173/`, causing Vite's base-path error.
2. **Hardcoded invite URL**: `InviteMember` builds invite links using `import.meta.env.BASE_URL || '/TeamForge/'`. If `BASE_URL` is not correctly resolved, links break.
3. **Hardcoded favicon in `index.html`**: `/TeamForge/images/teamforge-logo.png` fails in dev root.
4. **Invitation bug #1**: Duplicate membership race condition in `joinWorkspaceAsMemberOnLogin` and `joinWorkspaceByInviteService` due to check-then-create logic without compound unique index on `MemberModel(userId, workspaceId)`.
5. **Invitation bug #2**: `joinWorkspaceByInviteService` returns the generic `MEMBER` role for existing members, ignoring actual role (OWNER/ADMIN).
6. **Invitation bug #3**: OAuth state is the predictable invite code only (`state: inviteCode`), exposing CSRF risk.
7. **Invitation bug #4**: `loginController` swallows `joinWorkspaceAsMemberOnLogin` errors; user may login successfully but not join invited workspace, with no feedback.
8. **UX bug #1**: `SignIn`, `SignUp`, and `AuthRoute` navigate to `/workspace/${user.currentWorkspace}` without null check, producing `/workspace/null` or `/workspace/undefined` when `currentWorkspace` is missing.
9. **UX bug #2**: Password validation only requires `min(4)`, no strength requirements.
10. **UX bug #3**: Error handler returns raw internal error messages (e.g., Mongo connection errors) to clients.
11. **UX bug #4**: `UserModel.password` has `select: true`, risking hash leaks if queries omit `.select('-password')`.
12. **Session cleanup bug**: `auth.service.ts`, `workspace.service.ts`, and `role.seeder.ts` call `session.endSession()` redundantly in `try`/`catch` and `finally`, risking "Session already ended" errors.
13. **Cache bug**: `useGetWorkspaceMembers` hook has `staleTime: Infinity`, preventing members list from refreshing after new members join.
14. **Missing tests**: No test files exist for backend services or frontend invite components.

## Solution Approach

### Phase 1: Fix Base URL Configuration
1. **`frontend/vite.config.ts`**: Replace static base with conditional base:
   - `base: process.env.NODE_ENV === 'production' ? '/TeamForge/' : '/'`
   - During `npm run dev` (`NODE_ENV=development`) -> root `/`
   - During `npm run build` / CI (`NODE_ENV=production`) -> `/TeamForge/`
2. **`frontend/index.html`**: Change favicon `href` from `/TeamForge/images/teamforge-logo.png` to `%BASE_URL%images/teamforge-logo.png` so it resolves correctly in both environments.
3. **`frontend/src/components/workspace/member/invite-member.tsx`**: Update invite link generation to use `import.meta.env.BASE_URL || '/'` instead of hardcoded `/TeamForge/`.
4. **`frontend/src/components/logo/index.tsx`**: Update logo `baseUrl` fallback from `/TeamForge/` to `'/'`.
5. **`frontend/src/page/invite/InviteUser.tsx`**: Keep `returnUrl` as plain path `/invite/workspace/.../join` because HashRouter handles hash-based navigation; no base path needed in hash route.
6. **`frontend/src/components/auth/google-oauth-button.tsx`**: Simplify regex to `/^\/invite\/workspace\/([^/]+)\/join/` since `/TeamForge/` prefix lives before hash and is no longer part of hash path.
7. **`frontend/src/page/auth/SignIn.tsx`**: Update `returnUrl` regex to remove optional `/TeamForge/` prefix.
8. **`backend/.env`**: Update `FRONTEND_GOOGLE_CALLBACK_URL=http://localhost:5173/` (root) so local dev OAuth redirects land at root; production GitHub Actions workflow should set the callback to `https://harsh-91221.github.io/TeamForge/` (update workflow env).

### Phase 2: Apply Backend Fixes
1. **`backend/src/services/auth.service.ts`**:
   - Remove `session.endSession()` from `try` and `catch` in `loginOrCreateAccountService` and `registerUserService`; keep only `finally` cleanup.
   - In `joinWorkspaceAsMemberOnLogin`, replace check-then-create with atomic `findOneAndUpdate(upsert)` to prevent duplicate membership race condition.
2. **`backend/src/services/member.service.ts`**:
   - Fix `joinWorkspaceByInviteService` to return the existing member's actual role name when the user is already a member, instead of always returning `MEMBER`.
   - Replace check-then-create with atomic `findOneAndUpdate(upsert)` to prevent duplicate membership race condition.
3. **`backend/src/models/member.model.ts`**: Add compound unique index `{ userId: 1, workspaceId: 1 }` to enforce one membership per user/workspace and support atomic upsert.
4. **`backend/src/models/user.model.ts`**: Change `password` field default `select: true` to `select: false`.
5. **`backend/src/config/passport.config.ts`**: Replace predictable `state: inviteCode` with signed random state token (e.g., `jsonwebtoken.sign({ inviteCode, nonce: randomBytes(16).toString('hex') }, JWT_SECRET, { expiresIn: '10m' })`) and verify it in the callback.
6. **`backend/src/controllers/auth.controller.ts`**: Stop swallowing `joinWorkspaceAsMemberOnLogin` errors; propagate them so the login response indicates invite join failure and the frontend can show an error.
7. **`backend/src/middlewares/errorHandler.middleware.ts`**: Sanitize unknown errors in production by returning only a generic message (`'Internal server error'`) instead of `error?.message`.
8. **`backend/src/services/workspace.service.ts`** and **`backend/src/seeders/role.seeder.ts`**: Remove redundant `session.endSession()` calls in `try`/`catch`; keep only `finally` cleanup.
9. **`backend/src/validation/auth.validation.ts`**: Add password strength regex (minimum 8 chars, upper, lower, digit, special) to `passwordSchema`.
10. **`frontend/src/page/auth/SignIn.tsx`** and **`SignUp.tsx`**: Mirror password strength validation in Zod schemas and add `currentWorkspace` null guard before navigation.
11. **`frontend/src/routes/auth.route.tsx`**: Guard against missing `currentWorkspace` by redirecting to a workspace-creation page instead of `/workspace/null`.
12. **`frontend/src/page/auth/GoogleOAuth.tsx`**: Ensure `currentWorkspace` fallback handles null/empty gracefully.
13. **`frontend/src/types/api.type.ts`**: Align `LoginResponseType.user.currentWorkspace` and `UserType.currentWorkspace` types to reflect actual payload shape.
14. **`frontend/src/hooks/api/use-get-workspace-members.tsx`**: Change `staleTime: Infinity` to `staleTime: 0` so the members list refreshes when the workspace ID changes or the component remounts.
15. **`frontend/src/page/invite/InviteUser.tsx`**: After a successful join mutation, also invalidate the members query for the joined workspace by calling `queryClient.invalidateQueries({ queryKey: ['members', workspaceId] })`. The `workspaceId` should be obtained from the join mutation's response.

### Phase 3: Add Focused Automated Tests
- **Backend**: Vitest unit tests for `auth.service.ts` and `member.service.ts` covering invite code handling, duplicate membership upsert, role return for existing members, transaction rollbacks, and error propagation.
- **Frontend**: Vitest + React Testing Library tests for `InviteUser`, `InviteMember`, `SignIn`, `GoogleOauthButton`, and auth redirects covering invite link generation/parsing, invite context preservation across login/signup, and missing `currentWorkspace` guard.
- **Validation**: Run `npm test` in both `frontend` and `backend`; ensure all invite and auth tests pass.

## Validation Steps
1. **Base path verification**:
   - Start frontend dev server (`npm run dev`) and confirm no base-path warnings in console.
   - Verify assets load at `http://localhost:5173/` without 404s.
2. **Invite flow end-to-end**:
   - Owner copies invite link from workspace members UI and verifies it matches the expected base path (`http://localhost:5173/#/invite/workspace/...` in dev; `https://harsh-91221.github.io/TeamForge/#/invite/workspace/...` in production).
   - Recipient opens invite link while logged out; sees sign-in page with invite context preserved.
   - Recipient logs in via email/password or Google OAuth; backend joins workspace as MEMBER and updates `currentWorkspace`.
   - Recipient is redirected to `/workspace/{id}` and sees workspace dashboard.
   - **Verify recipient appears in workspace members** with role `MEMBER` (this tests the cache fix).
   - **Verify owner also sees the new member** in the members list (tests staleTime fix on both sides).
3. **Regression testing**:
   - Test email/password login and registration without invite code.
   - Test Google OAuth login without invite code.
   - Test workspace creation, project/task CRUD, and member role management.
   - Confirm no broken asset paths or navigation errors.
4. **Test suite execution**:
   - Run `npm test` in `frontend` and `backend`; all tests pass.
   - Run `npm run lint` and `tsc --noEmit` (frontend/backend); no errors.

## Dependencies
- Add test dependencies: Vitest, jsdom, React Testing Library for frontend; Vitest for backend (or Jest for backend if preferred).
- No database schema changes beyond adding compound unique index on `MemberModel(userId, workspaceId)`.

## Risk Assessment
- Low risk: Base-path fix is localized and confirmed safe for HashRouter.
- Atomic upserts and compound unique index eliminate duplicate membership race condition.
- All other fixes are direct applications of identified code review issues.
- Validation steps cover invite flow, auth flows, and existing functionality.
